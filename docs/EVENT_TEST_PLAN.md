# תוכנית בדיקות לאירוע

## 1. אוטומטי (כל שינוי)
- `npm test`: מנוע ולוגיקת שרת.
- `npm run test:db`: הרשאות, מכונת מצבים, אידמפוטנטיות, ניקוד כפול, איחור, השהיה, חשיפה, איפוס.

## 2. מול Supabase אמיתי (אחרי פריסה)
- [ ] אנונימי לא קורא טבלאות ולא את `private`. בודקים עם curl ומפתח anon.
- [ ] בכלי המפתחים של הטלפון, לשונית Network: לוודא שאין מפתח תשובה בשום תגובה לפני חשיפה.
- [ ] Realtime: שינוי אצל המנחה מגיע למסך תוך פחות משנייה.
- [ ] מצב טיסה באמצע סבב, ואז חזרה: אותה תשובה לא נרשמת פעמיים.
- [ ] רענון בכל אחד מהממשקים שוחזר למצב הנכון.

## 3. עומס מדורג
סקריפט שיתווסף: `scripts/load-test.ts` יוצר N משתמשים אנונימיים, רושם קבוצות ושולח הגשות במקביל.
- [ ] 10 קבוצות × 2 טלפונים, כולן מגישות בשנייה האחרונה.
- [ ] 17 קבוצות × 2 טלפונים.
- [ ] 20 קבוצות × 3 טלפונים (מרווח ביטחון).
מודדים: זמן תגובה של `game`, שגיאות Realtime (`too_many_*`), והתאמה בין ניקוד צפוי לניקוד בפועל.

## 4. מכשירים
- [ ] iPhone Safari, Android Chrome, טלפון ישן או איטי.
- [ ] גופן גדול במכשיר (נגישות), מצב כהה, Reduced Motion.
- [ ] המחשב שמחובר למקרן, ב־16:9 וברזולוציה של המקרן בפועל.

## 5. חזרה גנרלית (בשבוע של האירוע)
משחק דמה מלא: 9 סבבים, לפחות 5 קבוצות, גמר עם שתי זוכות, ואז איפוס. אחר כך לוודא שהטבלה ריקה.
